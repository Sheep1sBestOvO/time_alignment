# 实验一分析报告：单 session 偏移恢复（user_000, MPF）

## 1. 实验设置

| 项目 | 值 |
|---|---|
| 数据 | `discrete_gestures_user_000_dataset_000.hdf5` |
| 事件数 | 1900（全量 prompt） |
| 注入偏移 | `--shift-range -0.40 -0.10`（均匀，全部往前/变早） |
| 搜索窗 | `--uncertainty -0.10 0.50` |
| 特征 | MPF（stride 40 → 20ms/帧，1536 维） |
| 模板估计 | rERP，ridge 1e-3 |
| EM | iterations 5, beam 30, candidate-step 0.02 |
| 其他 | min-event-separation 0.02, prompt-prior-weight 0.05, seed 0 |

注入的偏移可分解为：**恒定偏移 ≈ −0.25s（系统性）+ 抖动 ≈ ±0.15s（随机，每事件不同）**。

## 2. 结果数据

```
       abs_error_before  abs_error_after  error_improvement
count       1900.000000      1900.000000        1900.000000
mean           0.249693         0.219883           0.029810
std            0.087102         0.083463           0.108927
min            0.100150         0.001500          -0.295446
5%             0.115325         0.073515          -0.105884
50%(median)    0.250596         0.213730           0.014536
95%            0.386829         0.366925           0.224529
max            0.399943         0.498590           0.369375
```

表面看：对齐前平均误差 0.250s，对齐后 0.220s，**仅改善 0.030s**；中位数 0.251→0.214。改善幅度相对 0.25s 的误差**微乎其微**。

## 3. 误差分解（关键）

绝对误差由两部分组成，必须分开看：

| 成分 | 大小 | 单 session 能否恢复 | 本次结果 |
|---|---|---|---|
| **恒定偏移**（≈0.25s） | 占误差**绝大部分** | **不能**（不可识别，被模板吸收） | 原样保留 — **设计使然，非失败** |
| **随机抖动**（std≈0.087s） | 小部分 | **理论上可以**（EM 拉回） | std 0.087→0.083，**几乎没恢复** |

**要点 1：0.22 的残差大头是那个"不可识别的恒定偏移"。** 用绝对误差衡量单 session，等于让一个注定测不出的常数主导了指标——所以结果"看起来惨"很大程度是**测错了量**，不能据此说算法坏。

**要点 2：真正的不足是抖动也没恢复。** `std` 从 0.087 几乎没降到 0.083，说明**相对时序没被恢复**。若 EM 成功，after 的（带符号）误差应收敛到一个近似常数、std 趋近 0（≈20ms 帧分辨率）。

## 4. 与 oracle 上界对照

之前本地诊断：用**未偏移真值**估模板再单次匹配（oracle），中位误差 ≈ **12ms**。

- oracle 成功 → **搜索/匹配核心是对的、有能力的**，给好模板能定位到帧级。
- 本次 EM 失败 → 差距**纯在模板质量**：从偏移位置自举出的 MPF 模板太糊、代价地形太平，EM 陷在差的局部解，事件基本不动。

## 5. 异常信号

- `max` 误差 after(0.499) > before(0.400)：**部分事件被对得更差**。结合日志里第 1 轮 `max update = 0.66s`，说明糊模板在首轮把一些事件打散到了错误位置，后续没收回。
- `error_improvement` 5% 分位 −0.106：约一成多事件明显变差。

## 6. 结论

1. **本实验无法证明对齐"有效"或"无效"**——它测的是一个被不可识别常数主导的绝对误差，且单 session 本就无法恢复系统性偏移。
2. **不能据此判定代码有问题**：oracle 证明搜索核心正确（12ms）。
3. **真正暴露的问题**：从偏移标签自举的 rERP 模板不够尖，EM 不收敛到干净解，连可恢复的抖动也没拉回。

## 7. 下一步建议

1. **零均值抖动**（`--shift-range -0.15 0.15`，`--uncertainty -0.25 0.25`）：去掉占大头的恒定偏移，单独、干净地检验 EM 能否恢复抖动。
2. **去偏指标**：判读单 session 用"减掉全局中位偏移后的 std"，而非绝对误差。
3. **oracle 对照**：永远带上 12ms 上界，区分"模板估计问题"还是"任务难度"。
4. **多 session + 全局 recenter**：测系统性偏移的"同步"（between-session spread 是否下降）——这是单 session 测不了的部分。
5. **改善 EM 收敛**：更窄的初始搜索窗 / 高置信子集引导首轮，避免一上来被打散。

---

**一句话总结**：第一次实验的"差"主要来自两点——(a) 注入了单 session 注定修不掉的恒定偏移，(b) 用被该常数主导的绝对误差来衡量。它既没证明算法有效、也没证明无效；真正学到的是"自估模板太糊导致 EM 不收敛"。下一轮应改用零均值抖动 + 去偏指标 + oracle 对照来得到可解读的结论。
